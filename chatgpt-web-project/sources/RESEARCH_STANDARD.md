# Research Standard

Research enough to write a technically accurate short video.

Prefer primary sources.

For GitHub repositories, check where relevant:

- repository description
- README
- screenshots and media
- documentation
- releases
- changelog
- linked website
- live demo
- examples
- source code when required to verify a claim

For websites or software products, check:

- homepage
- feature pages
- documentation
- demos
- pricing only when relevant
- release information
- public product status

## What to extract

Focus on:

1. What is it?
2. What problem does it solve?
3. What makes it interesting?
4. What are its strongest 2–4 features?
5. Why would a viewer care?
6. What can later be shown visually?
7. What important limitation or maturity status must be disclosed?

## Accuracy

Never transform:

planned → implemented

experimental → production-ready

project claim → independently established fact

prototype → complete product

Do not infer capabilities solely from names, screenshots, or marketing language.

If a claim cannot be verified, either omit it or record the uncertainty.

## Research Depth

Research should support a short video, not become a full technical audit.

Prioritize information that affects:

- the hook
- the story
- the narration
- what can be shown visually
